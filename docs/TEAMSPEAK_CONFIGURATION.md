# پیکربندی TeamSpeak — MAHYAR MUSIC (فاز ۱)

این سند همه‌ی چیزهایی که برای وصل‌کردن بات به سرور TeamSpeak لازم دارید را توضیح می‌دهد: کانال، هویت، پورت‌ها و دستورات چتی.

---

## ۱. کانال هدف (یک کانال ثابت)

بات باید همیشه به **یک کانال مشخص** برود. دو روش پشتیبانی می‌شود (موتور TS3AudioBot 0.12.0):

| روش | متغیر | قالب در پیکربندی | توصیه |
|---|---|---|---|
| شناسه‌ی عددی کانال | `TS3_CHANNEL_ID` | `channel = "/123"` | ✅ **پایدارترین روش** — تغییر نام/جابه‌جایی کانال اثر ندارد |
| مسیر کانال | `TS3_CHANNEL_PATH` | `channel = "Lobby/Afk Room"` | اگر ID را ندارید |

### پیدا کردن Channel ID

- در کلاینت TeamSpeak 3: روی کانال **راست‌کلیک → Copy Channel ID** (در نسخه‌های جدید)؛ یا از منوی کانال گزینه‌ی مشابه. عدد به‌دست‌آمده را در `TS3_CHANNEL_ID` بگذارید.
- اگر ID در دسترس نیست، مسیر کانال از ریشه را در `TS3_CHANNEL_PATH` بنویسید (مثال: `Main Lobby/Music`).

> اگر هر دو ست شوند، شناسه‌ی عددی اولویت دارد و در لاگ اطلاع داده می‌شود. اگر هیچ‌کدام ست نشوند، بات با خطای واضح بالا نمی‌آید (رفتار عمدی است؛ کانال پیش‌فرض خاموش اجدادی نیست).

## ۲. پورت‌های TeamSpeak — اشتباه رایج

| پورت | پروتکل | نقش |
|---|---|---|
| **9987** | **UDP** | صدا/ورود کلاینت — این همان `TS3_VOICE_PORT` است ✅ |
| 10011 | TCP | ServerQuery — رابط مدیریتی متنی؛ **ربطی به صدای بات ندارد** |
| 30033 | TCP | انتقال فایل |

> ⚠️ یک اتصال موفق ServerQuery یا رفع DNS به‌تنهایی اثبات صدای بات نیست. اثبات نهایی: بات در کانال دیده شود + صدای تست شنیده شود.

## ۳. هویت (Identity) — استفاده از هویت موجود

### سازگاری: تأییدشده

موتور انتخابی (TS3AudioBot 0.12.0) **رسماً از هویت کلاینت TeamSpeak پشتیبانی می‌کند**:

- کامنت رسمی خود کد پیکربندی: کلید `connect.identity.key` — *«The client identity. You can import a teamspeak3 identity here too.»*
- پارسر `TsCrypt.LoadIdentityDynamic` در TSLib دقیقاً قالب `<سطح امنیتی>V<base64>` (همان رشته‌ی هویت کلاینت) را می‌پذیرد.

پس هویت موجود شما بدون تبدیل قابل استفاده است. فرمت ورودی فایل:

- خروجی Export کلاینت (فایل ini شامل خط `identity=...`)، یا
- یک فایل متنی تک‌خطی شامل خود رشته‌ی `8VAAA...`

> رشته‌های هویت کلاینت گاهی پسوند `~...` دارند (وضعیت ذخیره‌شده‌ی کلاینت). اسکریپت اعتبارسنجی ما آن پسوند را حذف می‌کند چون پارسر موتور فقط بخش `عددVbase64` را می‌خواند. مقدار `offset=0` و `level=-1` در پیکربندی گذاشته می‌شود؛ یعنی موتور سطح امنیت لازم را خودش در لحظه‌ی اتصال محاسبه می‌کند.

### تهیه‌ی فایل هویت

1. کلاینت TeamSpeak 3 → **Tools → Identities**
2. هویت مورد نظر → **Export** → ذخیره‌ی ini در محل امن روی سیستم خودتان
3. طبق بخش ۶ سند [`RAILWAY_DEPLOYMENT.md`](RAILWAY_DEPLOYMENT.md) به volume منتقل کنید (`/data/secrets/identity.ini`)

### هشدار امنیتی (مهم)

- اگر هویت انتخابی **هویت شخصی روزمره‌ی شما** یا دارای دسترسی Server Admin است، از آن به‌عنوان هویت دائمی بات استفاده **نکنید**؛ یک هویت اختصاصی با حداقل دسترسی لازم بسازید. دلایل کامل: [`SECURITY.md`](SECURITY.md).
- کلید هویت = هویت شما. هرکس آن را داشته باشد می‌تواند با UID شما وصل شود. به همین دلیل هرگز commit/لاگ/public endpoint نمی‌شود.

## ۴. دستورات چتی (فاز ۱)

| دستور | توضیح |
|---|---|
| `!help` | فهرست دستورات (برای تست اولیه) |
| `!play test-tone.wav` | پخش صدای تست از `/data/bot/music/` |
| `!play <url>` | پخش URL (فاز ۱ فقط برای تست؛ ایستگاه‌های رادیویی در فاز ۲) |
| `!volume <0-100>` | تنظیم بلندی صدا |
| `!whisper off` | در فاز ۱ لازم نیست (`send_mode = "voice"` تنظیم شده) |
| `!bot disconnect` / `!bot connect` | قطع/وصل خود بات |
| `!bot setup` | ایجاد خودکار گروه دسترسی ServerBot روی سرور (اختیاری) |

پیشوند دستورها `!` است (پیش‌فرض موتور). تطبیق فرمان به‌صورت فازی `ic3` است (پیش‌فرض).

## ۵. پیکربندی تولیدشده — مرجع سریع

| کلید (TS3AudioBot 0.12.0) | منبع مقدار | توضیح |
|---|---|---|
| `connect.address` | `TS3_HOST` + `TS3_VOICE_PORT` | مثل `ts3.example.com:9987` |
| `connect.name` | `TS3_NICKNAME` | نام نمایشی بات |
| `connect.channel` | `TS3_CHANNEL_ID` یا `TS3_CHANNEL_PATH` | `"/<id>"` یا مسیر |
| `connect.server_password.pw` | `TS3_SERVER_PASSWORD` | در اولین اتصال خودکار هش می‌شود (`autohash`) |
| `connect.channel_password.pw` | `TS3_CHANNEL_PASSWORD` | مثل بالا |
| `connect.identity.key` | فایل `TS3_IDENTITY_FILE` | کلید خصوصی — perms 600 |
| `audio.send_mode` | ثابت: `"voice"` | شنیده‌شدن در کل کانال |
| `reconnect.ontimeout` | پیش‌فرض موتور | ری‌کانکت خودکار ۱ث تا ۵دقیقه (تکرار آخرین) |

فایل کامل با کامنت: [`../bot/config/ts3audiobot.example.toml`](../bot/config/ts3audiobot.example.toml)

## ۶. ری‌کانکت و رفتار پس از قطعی

- قطعی موقت شبکه/timeout: بازگشت خودکار با فواصل ۱ث، ۲ث، ۵ث، ۱۰ث، ۳۰ث، ۱د، ۵د و سپس تکرار ۵د.
- Kick: به‌صورت پیش‌فرض خودکار برنمی‌گردد (تصمیم عملیاتی؛ در `bot.toml` قابل تغییر به `onkick = ["10s", "repeat last"]`).
- Ban: هرگز خودکار برنمی‌گردد (درست است؛ تلاش برای دورزدن Ban نمی‌کنیم).
- خاموشی سرور TS3: تلاش مجدد پس از ۵ دقیقه.
- اگر خود پروسه بات crash کند: supervisor داخلی حداکثر ۵ بار با فاصله‌ی فزاینده ری‌استارت می‌کند و بعد کانتینر با exit 1 تمام می‌شود تا سیاست restart پلتفرم وارد عمل شود.
