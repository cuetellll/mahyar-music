# سند امنیتی — MAHYAR MUSIC (فاز ۱)

این سند الزامات امنیتی پروژه و نحوه‌ی پیاده‌سازی هرکدام را مستند می‌کند.

## ۱. هویت TeamSpeak — قوانین و پیاده‌سازی

فایل هویت شامل **کلید خصوصی** است؛ هرکس آن را داشته باشد می‌تواند با UID شما وصل شود. قوانین این پروژه:

| # | قانون | وضعیت پیاده‌سازی |
|---|---|---|
| 1 | هرگز تولید هویت جایگزین به‌صورت خاموش | ✅ اگر فایل هویت نباشد یا نامعتبر باشد، بات با خطای واضح بالا نمی‌آید؛ هیچ identity خودکاری ساخته نمی‌شود |
| 2 | هرگز بازنویسی هویت اصلی | ✅ فایل شما فقط خوانده می‌شود؛ entrypoint آن را تغییر نمی‌دهد (فقط `chmod 600`) |
| 3 | هرگز commit کردن فایل هویت | ✅ `.gitignore`: `secrets/`, `data/`, `identity*.ini`, `*.identity` |
| 4 | هرگز چاپ کلید خصوصی در لاگ | ✅ کد هیچ‌جا مقدار کلید را `echo` نمی‌کند؛ فقط سطح امنیت (عدد غیر محرمانه) و طول رشته گزارش می‌شود |
| 5 | هرگز نمایش هویت از HTTP عمومی | ✅ در فاز ۱ هیچ وب‌سروری فعال نیست (`web.api.enabled=false`, `web.interface.enabled=false`) و هیچ پورت عمومی وجود ندارد |
| 6 | هرگز داخل ایمیج Docker | ✅ ایمیج فقط باینری موتور و اسکریپت‌هاست؛ `.dockerignore` فایل‌های محرمانه را حذف می‌کند |
| 7 | ذخیره‌ی امن و پایدار | ✅ فقط روی volume در `/data/secrets/identity.ini` |
| 8 | دسترسی فایل محدود (600) | ✅ `umask 077` + `chmod 600` روی فایل هویت و `bot.toml` (که کلید داخلش کپی می‌شود) |
| 9 | خطای امن با پیام واضح در نبود/ناسازگاری هویت | ✅ exit code غیر صفر + پیام فارسی/انگلیسی راهنما |

**نکته:** چون بات کلید را در `bots/mahyar-music/bot.toml` نگه می‌دارد (نیاز خود موتور)، آن فایل هم `600` است و روی volume می‌ماند — هرگز از volume خارج نشود.

## ۲. روش امن تحویل هویت

- هویت فقط از راه Export کلاینت TS3 → آپلود به volume از طریق `railway ssh` (بخش ۶ [`RAILWAY_DEPLOYMENT.md`](RAILWAY_DEPLOYMENT.md)).
- paste کردن کلید در گفتگو، در کد، در issue یا در متغیر عمومی ممنوع است.
- حالت `MAHYAR_BOOTSTRAP=1` فقط برای همین آپلود اولیه است و بعد از آن باید خاموش شود.

## ۳. چرا هویت اختصاصی بات؟

اگر هویت انتخابی، هویت شخصی روزمره‌ی شما یا دارای دسترسی Server Admin باشد، اجرای دائمی بات با آن توصیه **نمی‌شود**:

1. **نفوذ = سوءاستفاده از دسترسی شما.** اگر کلید به هر دلیل لو برود، مهاجم با UID و دسترسی شما وارد می‌شود.
2. **Ban سرور = گروگان‌شدن هویت شما.** اگر بات عامل Ban شود، هویت شخصی شما هم می‌سوزد.
3. **اصل حداقل دسترسی:** بات فقط به چند دسترسی ساده نیاز دارد (اتصال، صحبت صوتی، پیام). یک هویت/اکانت تازه با همان گروه معمولی کافی است.

توصیه: در TeamSpeak یک هویت تازه با نامی مثل «Mahyar Music Bot» بسازید، با آن یک‌بار به سرور وصل شوید تا UID بگیرد و توسط مدیر سرور در گروه مناسب قرار گیرد، سپس همان را Export و آپلود کنید.

## ۴. شبکه

- اتصال صوتی کاملاً **outbound** از کانتینر به `TS3_HOST:TS3_VOICE_PORT (UDP)` است؛ هیچ پورت ورودی و هیچ TCP Proxy لازم نیست.
- وب‌اینترفیس و Web API موتور (پورت 58913 داخل کانتینر) در فاز ۱ **غیرفعال**‌اند. در فاز ۴ فعال‌سازی‌شان باید همراه احراز هویت و پشت لایه‌ی دسترسی کنترل‌شده انجام شود.
- ارسال آمار استفاده به سرور پروژه‌ی upstream با `send_stats=false` و `--stats-disabled` غیرفعال شده است.

## ۵. لاگ‌ها و رمزها

- لاگ فقط شامل وضعیت اتصال و خطاهای عمومی است.
- رمزهای سرور/کانال از env خوانده می‌شوند و هرگز لاگ نمی‌شوند.
- «اثر انگشت» پیکربندی (برای تشخیص تغییر) به‌صورت **hash یک‌طرفه** در `/data/bot/.mahyar-managed.sha256` ذخیره می‌شود؛ ورودی hash شامل کلید است اما خود hash قابل معکوس نیست.

## ۶. اجرای غیر root

- ایمیج یک کاربر اختصاصی `ts3ab` (بدون shell، با home) می‌سازد.
- entrypoint فقط برای آماده‌سازی `/data` و تولید پیکربندی به‌صورت root شروع می‌شود و بلافاصله قبل از اجرای بات با `gosu` به `ts3ab` سقوط می‌کند (الگوی رایج برای volume های root-owned در Railway).

## ۷. وابستگی‌ها و لایسنس

- موتور: [TS3AudioBot 0.12.0](https://github.com/Splamy/TS3AudioBot/releases/tag/0.12.0) — لایسنس **Open Software License 3.0 (OSL-3.0)**. ایمیج فقط باینری رسمی انتشارشده با checksum پین‌شده را دانلود می‌کند و اطلاعیه‌ی منبع/لایسنس upstream در README حفظ شده است.
- FFmpeg / libopus / libicu از مخازن رسمی Debian bookworm نصب می‌شوند.
- نسخه‌ها در `Dockerfile` پین شده‌اند؛ به‌روزرسانی فقط با تغییر نسخه‌ی پین‌شده و بازبینی checksum.
